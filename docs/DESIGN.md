# AWS Connect UI Design

## 1. 문서 지위

이 문서는 AWS Connect GUI의 공식 UI 설계 기준이자 단일 진실 공급원(SSOT)이다.

- 기능·상호작용 규범: 이 `docs/DESIGN.md`
- 픽셀·배치 시각 규범: [`aws-connect-ui-mockup.html`](design-docs/aws-connect-ui-mockup.html)
- 제품 요구사항: [`aws-connect.md`](product-specs/aws-connect.md)
- 구현 계획: [`aws-connect-application.md`](design-docs/aws-connect-application.md)

기능과 보안 규칙은 이 문서를, 크기·색상·위치·간격·아이콘·상태 표현은 HTML 목업을 우선 적용한다. 승인된 UI 변경은 두 파일을 같은 작업에서 함께 갱신한다. 목업의 계정, 호스트, 인스턴스, Secret 및 파일 정보는 모두 예시다.

## 2. UI 방향

AWS Connect는 하이브리드 Windows 데스크톱 애플리케이션으로 구성한다.

- 인증, 프로필, 대시보드, RDS 터널, Secrets Manager, S3 및 로그는 앱 내부에서 처리한다.
- EC2 대화형 셸만 별도 Windows Terminal에서 실행한다.
- 공통 인증 상태는 항상 상단에 표시한다.
- AWS 기능은 실행 직전에 동일한 세션 검증 절차를 거친다.
- 프로필 관리와 로그 확인은 AWS 인증이 없어도 사용할 수 있다.
- GUI는 비즈니스 규칙을 직접 구현하지 않고 CLI와 동일한 Application Service를 호출한다. 계층과 호출 규칙은 [`aws-connect-application.md`](design-docs/aws-connect-application.md)를 따른다.

## 3. 애플리케이션 셸

### 3.1 공통 레이아웃

1. 상단 인증 바
2. 왼쪽 기능 탐색
3. 오른쪽 작업 영역
4. 필요한 경우 모달 또는 앱 내부 상태 알림

목업의 정규 데스크톱 비교 viewport는 `1424 × 894`이며, 바깥 여백 `22px`을 제외한 앱 셸은
`1380 × 850`이다. 권장 최소 창 크기는 `1024 × 720`이고, 이때도 왼쪽 탐색을 유지하며
필요한 기능 화면의 내부 작업 영역만 스크롤한다.

### 3.2 상단 인증 바

상단 인증 바는 모든 화면에서 같은 위치와 내용으로 유지한다.

- 현재 사용자 지정 프로필 이름 또는 ID
- 인증 상태(토큰 만료 정보의 오른쪽에 같은 행으로 표시)
- Account ID
- IAM 사용자명
- 토큰 만료까지 남은 시간
- 프로필 관리 아이콘: 사용자와 톱니바퀴 조합
- 토큰 재발급 아이콘: 새로고침

Access Key, Secret Access Key와 Session Token 원문은 상단에 표시하지 않는다. 아이콘 버튼은 툴팁과 접근성 이름을 제공한다.

### 3.3 인증 상태

| 상태 | 상단 표시 | AWS 기능 동작 |
|---|---|---|
| 프로필 없음 | `인증정보 없음` | AWS 기능 비활성화, 프로필 관리 가능 |
| 검증 중 | `인증 확인 중` | 중복 실행 방지 |
| MFA 필요 | `MFA 인증 필요` | MFA 입력 후 원래 작업 재개 |
| 인증됨 | 초록 상태점과 `인증됨` | 기능 사용 가능 |
| 만료 임박 | 남은 시간 강조 | 기능 실행 전에 자동 갱신 절차 |
| 인증 실패 | 실패 원인 요약 | 앱은 유지하고 재시도·프로필 변경 제공 |

앱 시작 시 저장된 프로필과 토큰을 확인하되 MFA 입력을 무조건 강제하지 않는다. AWS 기능을 실행하는 순간 토큰이 유효하지 않으면 MFA 인증을 요청하고, 성공하면 사용자가 요청했던 작업을 이어서 실행한다.

## 4. 프로필 관리

프로필 관리 아이콘을 누르면 앱 내부 모달을 연다.

### 4.1 화면 구성

- 왼쪽: 저장된 프로필 목록, 현재 연결 상태, 새 프로필 버튼
- 오른쪽: 선택한 프로필의 상세 편집 영역
- 하단: 삭제, 복제, 저장, 이 프로필로 연결

### 4.2 데이터 필드

| 필드 | 규칙 |
|---|---|
| `seq` | SQLite 내부 PK, 자동 생성, 수정 불가 |
| `profile_id` | 사용자가 지정하는 고유 식별값, 중복 불가 |
| `account_id` | AWS Account ID, 숫자 12자리 검증 |
| `iam_user` | 예상 IAM 사용자명 |
| `access_key_id` | 저장·수정 가능, 기존 값은 원문 없이 등록 상태와 마스크만 표시 |
| `secret_access_key` | 저장·수정 가능, 기존 값은 원문 없이 등록 상태와 마스크만 표시 |
| `default_region` | 프로필의 기본 Region, 기능 화면에서 필요 시 변경 가능 |
| `mfa_arn` | Account ID와 IAM 사용자에서 내부 생성하며 일반 사용자 화면에는 표시하지 않음 |

RDS 터널과 저장된 S3 위치 등 다른 데이터는 변경 가능한 `profile_id`가 아니라 내부 `profile.seq`를 FK로 참조한다.

### 4.3 프로필 작업

- 저장: 입력값을 검증하고 민감값을 암호화한 뒤 저장한다.
- 새 프로필: 목록에 `저장되지 않음` 임시 항목을 만들고 저장 성공 후 실제 프로필로 교체한다.
- 복제: 선택한 프로필의 보호된 인증정보와 메타데이터를 새 ID의 비활성 프로필로 복사한다.
- 연결: 선택한 프로필의 자격증명을 검증하고 필요하면 MFA를 요청한다.
- 변경: 새 프로필 연결이 성공한 뒤 공통 상단 정보와 기능 데이터를 갱신한다.
- 삭제: 활성 EC2 또는 RDS 세션이 있으면 먼저 종료 여부를 확인한다.
- 저장 전 임시 프로필의 삭제는 로컬 편집 초안을 즉시 제거하며 AWS나 SQLite를 호출하지 않는다.
- 실패: 저장된 기존 프로필과 현재 앱 상태를 보존하고 구체적인 원인을 표시한다.

Secret Access Key와 발급 토큰은 Windows 사용자 범위 DPAPI로 암호화해 SQLite에 저장한다.

## 5. 대시보드

대시보드는 앱 실행 후 기본 화면이다.

- EC2, RDS, Secrets Manager, S3의 빠른 진입 제공
- 현재 프로필과 인증 상태는 상단 영역에서만 표시
- 실행 중인 RDS 터널을 하단에 요약
- 터널별 로컬 주소 복사와 연결 종료 제공
- 빈 상태에서는 프로필 등록 또는 기능별 첫 작업을 안내

기능 카드에 인증정보를 반복 표시하지 않는다. 대시보드의 핵심은 기능 소개보다 현재 연결 상태와 다음 행동이다.

## 6. EC2 접속

- Region, EC2 전원 상태(`전체`, `실행 중`, `중지됨`), 키워드 필터를 제공한다.
- 목록에는 SVG 즐겨찾기, Name, Instance ID, Private IP와 EC2 전원 상태를 표시한다. SSM 상태는
  작업 가능 여부와 버튼에만 반영하고 별도 열로 노출하지 않는다.
- 즐겨찾기는 프로필과 Region별로 저장하며 목록 상단에 표시한다.
- 실행 중이면서 SSM Online인 대상만 터미널을 열 수 있다.
- 실행 중이지만 SSM Offline인 대상은 명시적 확인 후 재부팅할 수 있고, 중지된 대상은
  과금 안내와 명시적 확인 후 시작할 수 있다. 중지 또는 종료 API는 제공하지 않는다.
- EC2 조회 권한이 없으면 기존 SSM Online 목록으로 축소하고 전원 상태 필터와 전원 작업을
  비활성화한다.
- `터미널 열기` 전에 공통 세션 검증을 실행한다.
- 성공하면 별도 Windows Terminal을 열고 앱에는 실행 결과를 기록한다.
- 터미널 창을 앱 내부에 임베드하지 않는다.

## 7. RDS 터널

### 7.1 화면 구성

- 왼쪽: 저장된 터널 세션 목록과 연결 상태
- 오른쪽: 선택한 세션의 상세 정보와 작업 버튼

### 7.2 세션 필드와 작업

- 사용자 지정 세션명
- 중계 EC2
- RDS Host
- `DescribeDBInstances` 권한이 있으면 RDS Host를 선택할 수 있고, 없으면 직접 입력을 유지한다.
- Remote Port
- Local Port
- 저장, 복제, 삭제, 연결 시작, 연결 종료

GUI에서는 중계 방식을 별도로 노출하지 않고 `중계 EC2` 한 항목을 필수 선택한다. 저장된
터널이 실행 중이면 하나의 주 작업 버튼이 `연결 시작`에서 `연결 종료`로 바뀐다. `새 세션`은
기존 레코드를 수정하지 않는 생성 모드이며, 미저장 편집값이 있으면 초기화 전에 확인한다.

실행 중에는 `127.0.0.1:로컬포트 → RDS host:원격포트`를 명확하게 표시하고 로컬 주소 복사를 제공한다. 앱 종료 시 남아 있는 터널 프로세스의 종료를 시도하고 결과를 로그에 기록한다.

## 8. Secrets Manager

- Secret 이름 또는 ARN 직접 입력을 항상 제공한다.
- 목록 권한이 있으면 자동으로 불러온 검색 가능한 Secret 목록을 왼쪽에 표시한다.
- 선택한 Secret의 JSON 결과를 오른쪽에 구조화해 표시한다.
- `password`, `secret`, `token`, `key` 성격의 값은 기본 마스킹한다.
- 값 동작은 선택 값 복사만 제공한다. JSON 변경 저장은 명시적 덮어쓰기 확인 후 AWS에 새
  Secret 버전으로 반영하며 원문을 로컬 DB나 로그에 저장하지 않는다.
- 조회 결과와 클립보드 내용은 SQLite와 로그에 저장하지 않는다.
- RDS 터널 세션에는 사용자가 선택한 `host`와 `port`만 복사할 수 있다.
- 직접 조회 권한이 없을 때 사용자가 명시적으로 Online EC2와 경유 조회를 선택하면 SSM Run
  Command로 고정된 Secret 조회 명령을 실행할 수 있다. 이 경로는 자동 fallback이 아니며,
  SSM command output에 원문이 일시 존재한다는 경고와 별도 동의를 표시한다.
- 중계 EC2 선택에는 Name, Instance ID와 플랫폼을 함께 표시한다. 앱 사용자에게
  `ssm:SendCommand`가 없으면 명시적 버튼으로 `ssm:StartSession`과
  `AWS-StartInteractiveCommand`를 사용해 같은 고정 명령을 외부 터미널에서 실행한다.
  이때 Secret 원문은 앱으로 회수하지 않고 터미널에서만 확인하며, StartSession도 거부되면
  필요한 권한과 수동 EC2 접속 경로를 안내한다.

## 9. S3 파일

- 화면 진입 시 `ListBuckets` 권한이 있으면 Bucket 선택 상자를, 없으면 직접 입력 상자를 표시한다.
- Prefix를 탐색 경로 형태로 표시한다.
- 객체 목록에는 이름, 유형, 크기, 수정 시간을 표시한다.
- Bucket 선택 즉시 객체를 조회하고 선택한 단일 객체를 확인 후 삭제할 수 있다. prefix 재귀 삭제는 금지한다.
- 로컬 파일 선택과 드래그 앤 드롭 업로드를 제공한다.
- 업로드 전에 최종 S3 URI와 덮어쓰기 여부를 확인한다.
- 업로드 중에는 파일별 진행률, 취소, 실패 원인을 표시한다.
- Bucket 목록 권한이 없어도 Bucket과 Prefix 직접 입력으로 작업할 수 있다.
- 프로필 변경이나 앱 종료는 앱이 소유한 업로드에 취소를 요청하며, multipart 정리가
  끝나기 전에는 완료로 표시하지 않는다.

## 10. 실행 로그

- No, 시간, 대상(탭), 내용, 결과 순서로 표시하며 각 행은 한글 텍스트가 잘리지 않는 높이를 갖는다.
- 사용자가 지정한 로그 폴더 열기 기능을 제공한다.
- Access Key, Secret Access Key, Session Token, MFA 코드 및 Secret 원문은 기록하지 않는다.
- 오류는 AWS 오류 코드와 사용자가 취할 수 있는 조치를 함께 표시한다.
- 목록은 시간, 기능, 대상, 결과를 우선 표시하고 선택한 행의 상세 패널에서 message code,
  correlation/operation ID, AWS service/action, 재시도 가능 여부와 마스킹된 원인을 표시한다.

## 11. 공통 상호작용 규칙

- 화면별 비즈니스 로직에서 인증 절차를 중복 구현하지 않는다.
- 파괴적 작업에는 명확한 확인 절차를 제공한다.
- 테이블 선택 행의 강조선은 첫 번째 셀 왼쪽에만 한 번 표시한다.
- 진행 중인 작업은 중복 실행되지 않도록 해당 작업 버튼만 잠근다.
- 긴 AWS 작업은 앱 전체를 멈추지 않고 진행 상태와 취소 가능 여부를 표시한다.
- 오류가 발생해도 앱을 종료하지 않으며 실패한 작업 범위만 중단한다.
- 토큰 갱신 성공 후 사용자가 처음 요청한 작업을 자동으로 재개한다.
- 성공·오류 알림은 간결한 앱 내부 알림으로 표시하고 상세 내용은 로그에서 확인한다.
- GUI는 Application의 `ProgressEvent`를 진행률 또는 단계 문구로 표시하고, `CancellationToken`을 통해서만 취소를 요청한다.
- GUI는 Application 오류 타입을 중앙 GUI mapper에서 모달, 토스트, 필드 오류와 후속 동작으로 변환한다.
- 입력값 오류는 mapper가 지정한 필드에 포커스·오류 테두리를 표시하고, 재시도 가능한
  오류는 앱 내부 토스트, 그 밖의 중단 오류는 비차단 모달로 표시한다.
- 화면 코드에서 AWS 오류 문자열이나 CLI 출력을 파싱하여 상태를 판정하지 않는다.
- RDS 터널은 앱이 소유하고 종료 시 정리하며, 별도 Windows Terminal에서 열린 EC2 세션은 사용자 소유로 전환한다.

## 12. 시각 기준

### 12.1 색상

| 용도 | 기준색 |
|---|---|
| 기본 작업 | Blue `#2563EB` |
| AWS 식별 포인트 | Orange `#FF9900` |
| 정상·연결됨 | Green `#18A66A` |
| 오류·삭제·종료 | Red `#D92D20` |

### 12.2 타이포그래피와 간격

- 기본 글꼴: Windows `맑은 고딕(Malgun Gothic)`을 Qt에 명시적으로 등록하고, 없을 때
  `Segoe UI`로 fallback
- 기본 본문: 14px
- 보조 문구: 12px 이상
- 화면 제목: 24–26px
- 기본 간격 단위: 4px
- 입력과 버튼 높이: 약 40px
- 카드 radius: 12–14px
- 입력과 버튼 radius: 8–10px
- 상단 인증 바: 92px, 왼쪽 탐색: 220px, 콘텐츠 여백: 위 30px·좌우 34px·아래 40px
- 아이콘 버튼: 42 × 42px, 기본 버튼 padding: 9px 14px, 작은 버튼: 7px 10px
- 카드: 2열 16px gap, 20px padding, 14px radius

한 화면에서 주 작업 버튼은 하나만 강하게 강조한다. 카드와 테두리는 정보 구분에 필요한 경우에만 사용한다.

## 13. 접근성과 키보드

- 모든 입력은 화면에 보이는 label을 가진다.
- 아이콘 전용 버튼은 접근성 이름과 툴팁을 가진다.
- Tab 키 순서는 화면의 읽기 순서를 따른다.
- Enter는 현재 폼의 기본 작업, Esc는 모달 닫기로 동작한다.
- 포커스 표시를 제거하지 않는다.
- 상태 변경과 오류는 스크린리더가 인지할 수 있도록 알린다.

## 14. 구현 검수 기준

- 상단 인증 바가 모든 기능 화면에서 동일하게 유지된다.
- 프로필 변경 후 Account ID, IAM 사용자와 토큰 만료 시간이 갱신된다.
- 인증 없이 AWS 기능을 실행하면 MFA 또는 프로필 등록 후 원래 작업이 이어진다.
- EC2 셸은 외부 터미널에서 실행되고 나머지 기능은 앱 내부에서 처리된다.
- RDS 터널 상태가 대시보드와 RDS 화면에서 일치한다.
- 민감정보가 화면, SQLite, 클립보드와 로그 정책을 위반하지 않는다.
- `1024 × 720`에서 필수 정보와 작업 버튼이 잘리거나 겹치지 않는다.
- 목업의 주요 화면과 사용자 흐름이 실제 구현에서 재현된다.
