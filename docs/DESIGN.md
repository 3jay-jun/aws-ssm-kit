# aws-ssm-kit UI Design

## 1. 문서 지위

이 문서는 aws-ssm-kit GUI의 공식 UI 설계 기준이자 단일 진실 공급원(SSOT)이다.

- 기능·상호작용 규범: 이 `docs/DESIGN.md`
- 픽셀·배치 시각 규범: [`aws-connect-ui-mockup.html`](design-docs/aws-connect-ui-mockup.html)
- 제품 요구사항: [`aws-connect.md`](product-specs/aws-connect.md)
- 구현 계획: [`aws-connect-application.md`](design-docs/aws-connect-application.md)

기능과 보안 규칙은 이 문서를, 크기·색상·위치·간격·아이콘·상태 표현은 HTML 목업을 우선 적용한다. 승인된 UI 변경은 두 파일을 같은 작업에서 함께 갱신한다. 목업의 계정, 호스트, 인스턴스, Secret 및 파일 정보는 모두 예시다.

## 2. UI 방향

aws-ssm-kit는 하이브리드 Windows 데스크톱 애플리케이션으로 구성한다.

- 인증, 프로필, 대시보드, RDS 터널, Secrets Manager, S3 및 로그는 앱 내부에서 처리한다.
- EC2 대화형 셸만 별도 Windows Terminal에서 실행한다.
- 공통 인증 상태는 항상 상단에 표시한다.
- AWS 기능은 실행 직전에 동일한 세션 검증 절차를 거친다.
- 프로필 관리와 로그 확인은 AWS 인증이 없어도 사용할 수 있다.
- GUI는 비즈니스 규칙을 직접 구현하지 않고 CLI와 동일한 Application Service를 호출한다. 계층과 호출 규칙은 [`aws-connect-application.md`](design-docs/aws-connect-application.md)를 따른다.

## 3. 애플리케이션 셸

### 3.1 공통 레이아웃

1. 상단 인증 바
2. 왼쪽 기능 탐색
3. 오른쪽 작업 영역
4. 필요한 경우 모달 또는 앱 내부 상태 알림

목업의 정규 데스크톱 비교 viewport는 `1424 × 894`이며, 앱 셸은 창의 전체 클라이언트 영역을 바깥 여백 없이 채운다. 로고 영역과 왼쪽 탐색 영역은 동일한 `220px` 폭을 사용한다. 권장 최소 창 크기는 `1024 × 720`이고, 이때도 왼쪽 탐색을 유지하며
필요한 기능 화면의 내부 작업 영역만 스크롤한다.

### 공통 탭 규격 (2026-09-18)

- 모든 탭의 실제 콘텐츠 루트: 좌우 24px, 상하 20px, 영역 간격 16px.
- 제목/설명은 공통 page_heading 사용: 제목 25px/700, 설명 13px, 사이 간격 4px.
- 소제목/카드 제목은 17px/700, 본문 13px, 필드 라벨/보조 정보 12px.
- 콘텐츠 배경은 #f7fafe로 통일한다. 각 탭의 별도 제목 크기/배경 덮어쓰기를 제거한다.
- 모든 QCheckBox, 표/목록의 체크 항목, 메뉴 체크 항목은 MFA 체크박스와 동일하다:
  16×16px, 1px 테두리, radius 4px, 선택 시 #2563eb 배경과 기존 common-check.svg 흰 체크.
- 공통 geometry는 presentation/gui/page_layout.py, 폰트 크기는 typography.py,
  실제 시각 스타일은 styles.py에서 관리한다. 탭별 바깥 여백·제목 스타일을 복제하지 않는다.

### 3.2 상단 인증 바

상단 인증 바는 모든 화면에서 같은 위치와 내용으로 유지한다.

- 현재 사용자 지정 프로필 이름 또는 ID
- 인증 상태(토큰 만료 정보의 오른쪽에 같은 행으로 표시)
- Account ID
- IAM 사용자명
- 토큰 만료까지 남은 시간
- 프로필 관리 아이콘: 사용자와 톱니바퀴 조합
- 토큰 재발급 아이콘: 새로고침

Access Key, Secret Access Key와 Session Token 원문은 상단에 표시하지 않는다. 아이콘 버튼은 툴팁과 접근성 이름을 제공한다.
프로필, Account ID, IAM 사용자, 토큰 만료와 인증 상태는 동일한 caption/value 2행 grid에
배치해 각 값의 세로 기준선을 맞춘다.

### 3.3 인증 상태

| 상태 | 상단 표시 | AWS 기능 동작 |
|---|---|---|
| 프로필 없음 | `인증정보 없음` | AWS 기능 비활성화, 프로필 관리 가능 |
| 검증 중 | `인증 확인 중` | 중복 실행 방지 |
| MFA 미사용·세션 없음 | `세션 발급 필요` | 사용자 입력 없이 세션 발급 후 원래 작업 재개 |
| MFA 필요 | `MFA 인증 필요` | MFA 입력 후 원래 작업 재개 |
| 인증됨 | 초록 상태점과 `인증됨` | 기능 사용 가능 |
| 만료 임박 | 남은 시간 강조 | 기능 실행 전에 자동 갱신 절차 |
| 인증 실패 | 실패 원인 요약 | 앱은 유지하고 재시도·프로필 변경 제공 |

앱 시작 시 저장된 프로필과 토큰을 확인하되 MFA 입력을 무조건 강제하지 않는다. AWS 기능을 실행하는 순간 토큰이 유효하지 않으면 MFA 인증을 요청하고, 성공하면 사용자가 요청했던 작업을 이어서 실행한다.

## 4. 프로필 관리

프로필 관리 아이콘을 누르면 앱 내부 모달을 연다.

### 4.1 화면 구성

- 왼쪽: 저장된 프로필 목록, 현재 연결 상태, 새 프로필 버튼
- 오른쪽: 프로필명 입력부터 시작하는 상세 편집 영역. 상단 타이틀과 생성/편집 모드·내부 SEQ 안내를 표시하지 않는다.
- 기존 팝업 크기를 유지하며 `+ 새 프로필` 버튼을 표시한다. 사용 중인 프로필은 `사용 중` 문구, 초록 점과 연한 파란 배경으로 표시하며 나머지는 회색 점으로 표시한다.
- MFA 체크 문구는 `세션 토큰 발급 시 MFA 사용 (선택)`이며 체크 시 파란 배경·흰 체크 표시를 사용한다.
- 목록은 작은 내부 여백의 프로필 이름·Account ID·IAM 사용자 3행으로 표시하고 마지막 항목을 제외한 하단에 옅은 구분선을 둔다.
- 각 목록 행의 더보기 메뉴에 `프로필 복제`, 빨간 `프로필 삭제`를 배치하며 독립 하단 버튼은 제거한다. 초안은 복제를 비활성화하고 삭제 시 로컬 초안만 버린다.
- 오른쪽 하단에는 아이콘과 텍스트가 있는 `저장`, 파란 primary `이 프로필로 연결` 버튼을 나란히 표시한다.
- 두 키 입력란의 눈 아이콘은 새로 입력한 텍스트의 echo mode만 토글하며 저장값을 복호화하지 않는다. 빈 입력란에서는 비활성화하고 프로필 선택 변경 시 입력값 및 노출 상태를 초기화한다.
- 자물쇠 아이콘과 연한 파란 안내 박스: `Secret Access Key와 세션 토큰은 현재 Windows 사용자 범위로 암호화해 로컬 SQLite에 저장합니다.`

### 4.2 데이터 필드

| 필드 | 규칙 |
|---|---|
| `seq` | SQLite 내부 PK, 자동 생성, 수정 불가 |
| `profile_id` | 사용자가 지정하는 고유 식별값, 중복 불가 |
| `account_id` | AWS Account ID, 숫자 12자리 검증 |
| `iam_user` | 예상 IAM 사용자명 |
| `access_key_id` | 저장·수정 가능, 기존 값은 원문 없이 등록 상태와 마스크만 표시 |
| `secret_access_key` | 저장·수정 가능, 기존 값은 원문 없이 등록 상태와 마스크만 표시 |
| `default_region` | 프로필의 기본 Region, 기능 화면에서 필요 시 변경 가능 |
| `mfa_enabled` | 임시 세션 발급 시 MFA 사용 여부, 새 프로필은 기본 활성화 |
| `mfa_arn` | Account ID와 IAM 사용자에서 내부 생성하며 일반 사용자 화면에는 표시하지 않음 |

RDS 터널과 저장된 S3 위치 등 다른 데이터는 변경 가능한 `profile_id`가 아니라 내부 `profile.seq`를 FK로 참조한다.

### 4.3 프로필 작업

- 저장: 입력값을 검증하고 민감값을 암호화한 뒤 저장한다.
- 새 프로필: 목록에 `저장되지 않음` 임시 항목을 만들고 저장 성공 후 실제 프로필로 교체한다.
- 복제: 선택한 프로필의 보호된 인증정보와 메타데이터를 새 ID의 비활성 프로필로 복사한다.
- 연결: 선택한 프로필의 자격증명을 검증하고 MFA 사용 프로필에만 코드를 요청한다.
- 변경: 새 프로필 연결이 성공한 뒤 공통 상단 정보와 기능 데이터를 갱신한다.
- 삭제: 활성 EC2 또는 RDS 세션이 있으면 먼저 종료 여부를 확인한다.
- 저장 전 임시 프로필의 삭제는 로컬 편집 초안을 즉시 제거하며 AWS나 SQLite를 호출하지 않는다.
- 실패: 저장된 기존 프로필과 현재 앱 상태를 보존하고 구체적인 원인을 표시한다.

Secret Access Key와 발급 토큰은 Windows 사용자 범위 DPAPI로 암호화해 SQLite에 저장한다.

## 5. 대시보드

대시보드는 앱 실행 후 기본 화면이다. 제목은 대시보드,
설명은 현재 AWS 프로필로 사용할 수 있는 기능과 최근 작업 현황을 확인합니다.

- 공통 헤더/사이드바 유지. EC2 접속/RDS 터널/Secrets Manager/S3 파일 4개 상태 카드를
  한 행에 표시한다. 좁은 창은 가로/세로 스크롤로 모든 버튼에 접근한다.
- 카드에는 기존 기능 SVG, 설명, 전체 상태, 권한 항목, 하단 텍스트 이동 버튼을 표시한다.
- 전체 상태는 전 항목 가능=사용 가능, 가능과 미확인/불가 혼재=일부 가능,
  전 항목 불가=사용 불가, 나머지=확인 필요. 미확인을 권한 없음으로 표시하지 않는다.
- 우측 권한 상태 새로 확인 버튼과 마지막 확인 시각. 비동기 작업 중 버튼 비활성화,
  프로필 변경 시 기존 판정/시각 초기화 및 지연 콜백 무효화.
- 안전한 조회는 DescribeInstances/DescribeInstanceInformation/ListSecrets/ListBuckets.
  나머지는 동일 프로필·리전의 최근 24시간 구조화 완료 로그에서 정확한 AWS API별로 판정.
  대상별 결과가 다르면 확인 필요. 결과 tooltip에 관측 범위를 명시한다.
- StartPortForwardingSession은 표시 명칭이며 실제 StartSession의 RDS 실행 결과를 참고한다.
  Secret 생성/수정은 CreateSecret/UpdateSecret 두 작업의 근거가 모두 있어야 판정한다.
- 활성 RDS 터널 영역과 해당 영역의 조작은 제거한다. RDS 페이지 기능은 유지한다.
- 최근 작업은 기존 SQLite ExecutionLogService.list_recent(5), 최신 완료 이벤트 5건.
  시간/결과/기능/작업/대상/내용 표, 실행 로그 전체 보기 버튼으로 기존 로그 페이지 이동.
  상태 배지는 실행 로그와 같은 공통 status_badge 및 결과 ViewModel을 사용한다.

## 6. EC2 접속

- 2026-09-17 승인된 EC2 신규 시안을 기준으로 밝은 배경, 넓은 카드, 48px 새로고침을 사용한다. 공통 셸은 유지한다.
- 편집 가능한 Region 드롭다운, 상태(`전체`, `실행 중`, `중지됨`), 검색 아이콘 입력,
  `즐겨찾기만`을 한 줄에 표시한다. 검색 안내는 `이름, Instance ID, Private IP로 검색`이다.
- 열 순서는 즐겨찾기, 이름, Instance ID, Private IP, EC2 상태, SSM, 최근 접속, 작업이다.
- EC2 전원 상태와 SSM 준비 상태는 독립적인 DTO 정보로 표시한다. 실행 중/중지됨은 상태점,
  준비됨/지원 안됨은 SVG 아이콘과 배지로 표시한다. SSM Online만 준비됨으로 표현한다.
- 즐겨찾기는 프로필·Region별 저장과 우선 정렬을 유지하며 선택된 별은 파란 채움,
  나머지는 외곽선이다. 선택 행은 첫 셀 파란 선과 연한 파란 배경이다.
- 실행 중+SSM 준비됨은 파란 외부 터미널 버튼, 중지됨은 시작 버튼이다.
  실행 중+SSM 불가는 비활성 버튼과 설명을 제공한다. GUI 재부팅 버튼은 표시하지 않는다.
- 기존 CLI 시작/재부팅 계약은 유지한다. Stop/Terminate, 대량 작업, 임베디드 터미널은 제공하지 않는다.
- 작업의 더보기는 인스턴스 ID 복사, Private IP 복사, 태그 보기를 제공한다.
  복사는 공통 30초 조건부 클립보드 삭제 정책을 사용한다. IP가 없으면 복사를 비활성화한다.
  태그는 기존 DescribeInstances DTO를 사용하는 비차단 읽기 전용 팝업으로 표시한다.
- 최근 접속은 Application이 공통 활동 로그에서 프로필·Region·인스턴스별 성공만 조회한다.
  로컬 날짜로 `오늘 HH:mm`, `어제 HH:mm`, `YYYY-MM-DD`를 표시하고 이력이 없으면 `-`이다.
  scoped 성공 이벤트가 없는 구형 로그는 성공을 추측하지 않는다. 보관 로그 범위 밖 이력은 표시하지 않는다.
- 하단은 `선택한 인스턴스: {instance_id} · {name} · 마지막 연결 성공 ({시간})`이며,
  성공 이력이 있을 때 초록 체크를 표시한다. 이력이 없으면 `연결 이력 없음`, 미선택이면 안내한다.
  실패는 공통 오류 전달 경로로 표시하고 하단을 원문 FAILED/PID 상태로 대체하지 않는다.
- 목록 조회, 접속, 시작은 공통 인증/MFA 흐름을 따른다. 프로필/Region 전환 후 이전 조회 결과는 버린다.
- EC2 조회 권한이 없으면 기존 Online SSM fallback을 유지한다. 이름은 가변 폭·말줄임,
  작은 화면의 표는 내부 가로 스크롤로 작업에 접근한다.

## 7. RDS 터널

### 7.1 화면 구성

- 왼쪽: 맨 위에 파란 배경의 텍스트 전용 `새 세션` 버튼, 그 아래 검색창과 저장된 터널 세션 목록을 배치한다. `저장 세션 검색` 제목과 별도 상단 여백은 두지 않는다.
- 목록 행은 프로필 목록과 같은 작은 내부 여백·옅은 하단 구분선을 사용하고 마지막 행은 구분선을 생략한다.
- 목록 행 더보기: 터널 이름 변경·세션 복제·세션 삭제를 제공한다. 별도의 목록 하단 삭제·복제 버튼은 표시하지 않는다.
- 오른쪽: 선택한 세션의 상세 정보와 로컬 주소 복사·저장·연결 버튼. 연결된 세션의 초록 점과 제목/설명 블록 사이에 20px 여백을 둔다. 목록에서도 연결된 항목 왼쪽에 동일한 초록 점을 12px 간격으로 표시한다.

### 7.2 세션 필드와 작업

- 사용자 지정 세션명
- 중계 EC2
- RDS Host
- `DescribeDBInstances` 권한이 있으면 RDS Host를 선택할 수 있고, 없으면 직접 입력을 유지한다.
- 긴 endpoint 표시 문자열은 콤보박스의 크기 힌트를 키우지 않으며 선택 상자는 편집 패널 폭 안에서 줄어든다.
- Remote Port
- Local Port
- 두 포트는 숫자 직접 입력만 표시하고 우측 증감 버튼은 숨긴다. 기존 범위 검증은 유지한다.
- 저장·연결 작업은 공통 아이콘 버튼과 툴팁·접근성 이름을 제공한다. 연결 종료는 빨강/흰색, 연결 시작은 파랑/흰색이다. 접속 정보 복사는 기본 Host/Port 두 줄이며 메뉴에서 Host, Port, 로컬 주소, 전체 매핑 문자열을 선택한다. 복제·삭제는 목록 행 더보기에서 제공한다.

GUI에서는 중계 방식을 별도로 노출하지 않고 `중계 EC2` 한 항목을 필수 선택한다. 저장된
터널이 실행 중이면 하나의 주 작업 버튼이 `연결 시작`에서 `연결 종료`로 바뀐다. `새 세션`은
목록 맨 위에 `새 세션 · 저장되지 않음` 임시 항목 하나를 만든다. 저장 전에는 SQLite에 기록하지 않으며 주기적 상태 갱신에도 편집값과 임시 항목을 유지한다. 저장 성공 후 저장된 항목을 선택하여 후속 저장은 갱신으로 처리한다. 임시 항목 삭제는 DB에 영향을 주지 않는다. 미저장 편집값이 있으면 새 세션 생성·삭제 전에 확인한다.

실행 중에는 `127.0.0.1:로컬포트 → RDS host:원격포트`를 명확하게 표시하고 로컬 주소 복사를 제공한다. 앱 종료 시 남아 있는 터널 프로세스의 종료를 시도하고 결과를 로그에 기록한다.
연결 상태 안내는 작업 버튼 위에 한 행 높이로 표시한다.
기존 세션의 편집값이 바뀐 상태에서 연결을 시작하면 편집값 저장이 성공한 뒤 저장 결과의 ID로
연결한다. 저장 실패 시 이전 값으로 연결하지 않는다.
로컬 포트를 변경하면 사용 가능 여부를 다시 검사하며 완료 전에는 연결 버튼을 비활성화한다.

## 8. Secrets Manager

화면은 왼쪽 SQLite `저장된 Secret` 목록과 오른쪽 선택 Secret 값의 master-detail 구조를 사용한다.
AWS 목록 조회 권한이 있으면 상단을 선택 상자로, 없으면 이름/ARN 직접 입력으로 전환한다. 조회에
성공한 ID, Value, 조회 방식과 중계 EC2는 왼쪽 목록에 자동 저장한다. 저장 항목을 선택하면 이 값을
AWS 재조회 없이 복원하며 ID와 Value 수정은 SQLite에만 반영한다. 중계 EC2는 프로필 선택 시 자동
조회하므로 별도 수동 새로고침 버튼을 두지 않는다.

- Secret 이름 또는 ARN 직접 입력은 목록 권한이 없을 때 제공한다.
- 목록 권한이 있으면 자동으로 불러온 Secret 선택 상자를 상단에 표시한다.
- 선택한 Secret의 JSON 결과를 오른쪽에 구조화해 표시한다.
- `password`, `secret`, `token`, `key` 성격의 값은 기본 마스킹한다.
- 민감 값은 행을 두 번 눌렀을 때만 30초 동안 표시한다. 하단 `전체 내용 복사`(아이콘+텍스트)는 조회 원문 전체를 명시적으로 복사하고 공통 30초 조건부 클립보드 정리를 사용한다. AWS 변경 버튼은 제공하지 않는다.
- 조회 Value는 저장 목록의 SQLite 레코드에 평문으로 저장하지만 로그에는 기록하지 않는다.
- 기존 host/port 전송 버튼은 전체 내용 복사 버튼으로 대체한다.
- 직접 조회 권한이 없을 때 사용자가 명시적으로 Online EC2와 경유 조회를 선택하면 SSM Run
  Command로 고정된 Secret 조회 명령을 실행할 수 있다. 이 경로는 자동 fallback이 아니며,
  SSM command output에 원문이 일시 존재한다는 경고와 별도 동의를 표시한다.
- 중계 EC2 선택에는 Name, Instance ID와 플랫폼을 함께 표시한다. 앱 사용자에게
  `ssm:SendCommand`가 없으면 명시적 버튼으로 `ssm:StartSession`과
  `AWS-StartInteractiveCommand`를 사용해 같은 고정 명령을 외부 터미널에서 실행한다.
  명령 완료 뒤 플랫폼별 셸을 이어 열어 터미널을 유지한다. 이때 Secret 원문은 앱으로 회수하지
  않고 터미널에서만 확인하며, StartSession도 거부되면
  필요한 권한과 수동 EC2 접속 경로를 안내한다.

- 제목/설명 간격은 EC2·RDS와 같은 4px이다. 조회 방식·Secret 검색 입력·조회 버튼은 하단 기준선을 맞추고 안내 문구는 별도 행에 둔다.
- 조회는 파랑/흰색 아이콘, 목록 하단 삭제는 빨강/흰색 아이콘, 등록은 아이콘만 표시하고 모두 툴팁·접근성 이름을 제공한다.
- 등록과 목록 더블 클릭은 공통 `Secret 등록`/`Secret 수정` 팝업을 연다. ID는 SQLite 자동 생성 SEQ(읽기 전용), Secret ID·Value는 편집 가능하며 저장·취소 버튼을 제공한다.
- 목록은 Secret ID의 마지막 이름을 타이틀로, 짧은 Secret ID를 하단에 표시한다. 프로필 공통 compact 행·마지막 행 제외 구분선을 재사용한다. ARN 접두부는 화면에서 생략하되 원본 조회/저장 식별자는 보존한다. 조회 결과 상단에는 Secret 이름과 축약 Secret ID, 마지막 조회 시각을 표시한다.

## 9. S3 파일

2026-09-18 사용자 제공 최종 S3 화면 및 검색 모달 PNG를 기준으로 한다.
상단에는 제목/설명과 파란 `업로드` 버튼만 두며 실행 중 `업로드 취소`로 전환한다.

- `S3 Bucket` 헤더에 Bucket 선택과 클릭 가능한 breadcrumb를 통합한다.
  Bucket 목록 권한이 없으면 같은 편집 가능한 선택 상자로 직접 입력한다.
- 헤더 오른쪽 작업 순서: 검색/경로 이동, 다운로드, 단일 파일 삭제, 새로고침.
- 검색 버튼은 `S3 검색 / 경로 이동` 모달을 연다. 경로 이동/파일 검색 탭, 현재 위치,
  Bucket, Prefix, 최근 경로(프로필 전환 시 초기화되는 메모리)를 제공한다.
  파일 검색은 현재 Prefix 하위 전체에서 파일명 부분 일치(대소문자 무시)로 조회한다.
- 객체 표: 체크박스, 이름+파일/폴더 SVG, 유형, 크기, 수정 시간, 작업.
  행 메뉴: 다운로드, 이름 변경, 복사 경로, 빨간 삭제. 폴더 이름 변경/삭제는 비활성화.
  다중 선택 시 다운로드만 가능하며 batch/prefix 재귀 삭제는 제공하지 않는다.
- `업로드 파일 (n개)` 카드 안에 큐 표를 표시한다. 오른쪽에 파일/폴더 추가와 더보기.
  더보기는 완료 항목 숨기기, 실패 항목만 보기, 빨간 목록 전체 비우기이다.
- 큐 표: 체크박스, 미리보기, 파일명, 크기, 로컬 경로, 수정 시간, 상태, 진행률, 작업.
  bounded worker 이미지 미리보기/파일 아이콘, 실패 항목 재시도, 빨강/흰색 휴지통 제거.
  큐 제거는 로컬 메모리 목록만 변경하며 S3 삭제를 호출하지 않는다.
- 파일/폴더 혼합 선택은 folder+ 버튼으로 실행하며 drag & drop을 유지한다. 빈 표 클릭은 파일 선택창을 열지 않는다. 폴더는 서비스 preflight에서
  실제 파일 행으로 확장한다. 전송 중에는 목록 추가/제거/비우기를 막고 취소를 제공한다.
- 성공/실패/대기(무시가 있으면 무시 포함) 개수와 파일별 백분율 평균을 하단 전체 진행률로 표시한다.
  실패 항목은 재시도 가능하며 이미 성공한 항목을 재업로드하지 않는다. 재시도는 원 대상 경로를 유지한다.
- 업로드 충돌 및 다운로드 로컬 중복의 덮어쓰기/무시/취소, MFA 재개와 취소를 유지한다.
  작은 화면에는 테이블 가로 스크롤과 페이지 내부 세로 스크롤을 제공한다.
- 이름 변경은 동일 Prefix 내 5 GiB 이하 단일 파일에 조건부 복사 후 조건부 삭제를 수행한다.
  대상이 생기거나 원본이 변경되면 덮어쓰기/원본 삭제를 차단한다. 복사 후 삭제 실패는 두 파일 확인 안내.


## 10. 실행 로그

- No, 시간, 대상(탭), 내용, 결과 순서로 표시하며 각 행은 한글 텍스트가 잘리지 않는 높이를 갖는다.
- 사용자가 지정한 로그 폴더 열기 기능을 제공한다.
- Access Key, Secret Access Key, Session Token, MFA 코드 및 Secret 원문은 기록하지 않는다.
- 오류는 AWS 오류 코드와 사용자가 취할 수 있는 조치를 함께 표시한다.
- 목록은 시간, 기능, 대상, 결과를 우선 표시하고 선택한 행의 상세 패널에서 message code,
  correlation/operation ID, AWS service/action, 재시도 가능 여부와 마스킹된 원인을 표시한다.

## 11. 공통 상호작용 규칙

- 화면별 비즈니스 로직에서 인증 절차를 중복 구현하지 않는다.
- 파괴적 작업에는 명확한 확인 절차를 제공한다.
- 테이블 선택 행의 강조선은 첫 번째 셀 왼쪽에만 한 번 표시한다.
- 진행 중인 작업은 중복 실행되지 않도록 해당 작업 버튼만 잠근다.
- 긴 AWS 작업은 앱 전체를 멈추지 않고 진행 상태와 취소 가능 여부를 표시한다.
- 오류가 발생해도 앱을 종료하지 않으며 실패한 작업 범위만 중단한다.
- 토큰 갱신 성공 후 사용자가 처음 요청한 작업을 자동으로 재개한다.
- 성공·오류 알림은 간결한 앱 내부 알림으로 표시하고 상세 내용은 로그에서 확인한다.
- GUI는 Application의 `ProgressEvent`를 진행률 또는 단계 문구로 표시하고, `CancellationToken`을 통해서만 취소를 요청한다.
- GUI는 Application 오류 타입을 중앙 GUI mapper에서 모달, 토스트, 필드 오류와 후속 동작으로 변환한다.
- 입력값 오류는 mapper가 지정한 필드에 포커스·오류 테두리를 표시하고, 재시도 가능한
  오류는 앱 내부 토스트, 그 밖의 중단 오류는 비차단 모달로 표시한다.
- 화면 코드에서 AWS 오류 문자열이나 CLI 출력을 파싱하여 상태를 판정하지 않는다.
- RDS 터널은 앱이 소유하고 종료 시 정리하며, 별도 Windows Terminal에서 열린 EC2 세션은 사용자 소유로 전환한다.

### 12.2 타이포그래피와 간격

- 기본 글꼴: Windows `맑은 고딕(Malgun Gothic)`을 Qt에 명시적으로 등록하고, 없을 때
  `Segoe UI`로 fallback
- 기본 본문: 14px
- 보조 문구: 12px 이상
- 화면 제목: 24–26px
- 기본 간격 단위: 4px
- 입력과 버튼 높이: 약 40px
- 카드 radius: 12–14px
- 입력과 버튼 radius: 8–10px
- 상단 인증 바: 92px, 왼쪽 탐색: 220px, 콘텐츠 여백: 위 30px·좌우 34px·아래 40px
- 아이콘 버튼: 42 × 42px, 기본 버튼 padding: 9px 14px, 작은 버튼: 7px 10px
- 카드: 2열 16px gap, 20px padding, 14px radius

한 화면에서 주 작업 버튼은 하나만 강하게 강조한다. 카드와 테두리는 정보 구분에 필요한 경우에만 사용한다.

## 13. 접근성과 키보드

- 모든 입력은 화면에 보이는 label을 가진다.
- 아이콘 전용 버튼은 접근성 이름과 툴팁을 가진다.
- Tab 키 순서는 화면의 읽기 순서를 따른다.
- Enter는 현재 폼의 기본 작업, Esc는 모달 닫기로 동작한다.
- 포커스 표시를 제거하지 않는다. 키보드 이동 시 선택 행의 내부와 여백은 같은 배경색을 유지한다.
- 상태 변경과 오류는 스크린리더가 인지할 수 있도록 알린다.

## 14. 구현 검수 기준

- 상단 인증 바가 모든 기능 화면에서 동일하게 유지된다.
- 프로필 변경 후 Account ID, IAM 사용자와 토큰 만료 시간이 갱신된다.
- 인증 없이 AWS 기능을 실행하면 MFA 또는 프로필 등록 후 원래 작업이 이어진다.
- EC2 셸은 외부 터미널에서 실행되고 나머지 기능은 앱 내부에서 처리된다.
- 대시보드는 다른 기능 Widget 내부 상태를 참조하지 않는다.
- 민감정보가 화면, SQLite, 클립보드와 로그 정책을 위반하지 않는다.
- `1024 × 720`에서 필수 정보와 작업 버튼이 잘리거나 겹치지 않는다.
- 목업의 주요 화면과 사용자 흐름이 실제 구현에서 재현된다.

### RDS 시각 보완 (2026-09-17 사용자 검증)

RDS 이름 변경 메뉴와 팝업 제목은 `터널 이름 변경`, 입력 label은 `새 터널 이름`이다.
연결 상태 카드에서 링크 SVG 아이콘은 파란색, `연결됨`만 굵게 표시하고 매핑은 일반 텍스트를 유지한다.
안내 i 아이콘은 공통 색상 적용 후에도 글자가 보이도록 투명 cutout을 사용한다.

### Secrets Manager 신규 시안 (2026-09-17)

- 설명: `현재 조회 방식으로 접근 가능한 Secrets Manager 항목을 표시합니다.`
- 직접 조회는 검색 영역만 표시한다. EC2 경유에서는 중계 선택/SSM 상태/연결 테스트/동의/정보 박스를 추가한다.
  조회 방식이나 중계 변경 시 동의를 초기화한다. 중계 선택 항목은 이름·ID·플랫폼을 표시한다.
- 검색은 검색 SVG와 `이름 또는 Secret ID로 검색 (예: brandbay_rds_prod)` 안내를 표시한다.
  직접 조회의 선택 상자는 편집 가능하며 직접 ID 입력도 지원한다. 직접 자격증명의 ListSecrets 목록을
  EC2 role의 목록으로 간주하지 않으며 EC2 경유는 ID 입력으로 조회한다.
- 연결 테스트는 Application의 기존 Online/platform 검증을 다시 실행한다. Secret 원문을 읽거나
  임의 명령을 실행하지 않는다. IAM SendCommand/GetSecretValue 권한은 실제 조회에서 검증된다.
  실패하면 typed 오류를 표시하고 조회를 차단한다. 동의는 SSM output 원문 일시 노출 안내와 함께 제공한다.
- 왼쪽은 `+ 수동 생성`, compact 2줄 이름/Secret ID 목록, 행별 더보기이다. 저장 개수 제목은 표시하지 않는다.
  더보기는 ID 복사/이름 복사/로컬 저장 삭제만 제공한다. 하단 독립 삭제/저장 버튼은 표시하지 않는다.
  삭제는 기존 확인을 유지하고 AWS에는 영향을 주지 않는다. 목록 안에서 스크롤하며 선택선은 파란색이다.
- 상세는 키-값/원문(JSON) 탭, 마지막 조회 시각, 값 숨기기를 제공한다. 키-값은 읽기 전용이며
  행별 복사와 민감 값 눈 아이콘을 제공한다. 원문도 기본 마스킹하며 별도 명시적 표시 후 30초에 숨긴다.
  값 숨기기는 두 탭의 모든 노출을 즉시 해제한다. 프로필 전환/새 결과는 이전 노출과 원문을 폐기한다.
- 전체 복사 split button은 원문/JSON/키-값 형식을 제공한다. 값 복사도 기존 30초 조건부 클립보드 정리를 사용한다.
- 조회 성공 시 UTC 시각을 저장하고 로컬 시간으로 표시한다. 수동 생성/수정은 조회 시각을 만들거나 갱신하지 않는다.
  이전 저장 데이터에는 조회 이력이 없음을 `-`로 표시한다. 작은 창은 화면 내부 세로 스크롤을 제공한다.

## 실행 로그 데이터 계약 (2026-09-18)

실행 로그와 대시보드 최근 작업은 같은 ExecutionLogService/SQLite 조회를 사용한다. 파일 열기는 기존 기능을 유지한다. 레벨(DEBUG/INFO/WARNING/ERROR), 결과(SUCCESS/WARNING/FAILURE/CANCELLED), 단계(STARTED/PROGRESS/COMPLETED)를 구분한다. 상세 정보에 단계, 오류 분류, 오류 코드, 필요한 IAM 권한을 추가하며 Request ID/Correlation ID/Operation ID를 표시한다. 기간·레벨·기능·검색 필터와 오류만 보기를 조합하고 새로고침 시 유지한다. 조회 제한은 필터 적용 후 계산한다. 토스트 자체는 gui.notice로 기록하지 않는다.


### 실행 로그 시각 보정 (2026-09-18)

- 필터 상단 라벨은 기간/레벨/기능/검색이며 오류만 보기와 새로고침은 우측 유지.
- 기능/결과는 실제 스타일 적용 SVG·텍스트 위젯의 필요 폭과 셀 여백을 확보한다.
  대상/내용만 남는 너비를 확장 사용한다. 일곱 기능명과 세 결과가 잘리지 않아야 한다.
- 목록 우선: 행 높이 40px. 1204×780 콘텐츠 영역에서 펼침 7행 이상, 접힘 10행 이상.
- 상세 상단은 레벨/기능/작업/대상/결과/시간 한 줄 요약과 복사·접기 버튼이다.
  기본 펼침, 접으면 요약만 남으며 선택/새로고침 시 접기 상태를 유지한다.
- 펼침 본문은 메시지 강조 박스와 Operation ID/Correlation ID/AWS 서비스/AWS Action/
  AWS Request ID/단계 2열 grid. 빈 값은 -로 유지하며 긴 내용은 본문 내부 스크롤로 확인한다.
- 오류 분류/오류 코드/필요 권한은 성공 시 숨기고, 그 외 결과에서 실제 값이 있을 때만
  오류 정보에 표시한다. 상세 복사는 접힘 여부에 상관없이 전체 마스킹된 정보를 제공한다.
- 표와 상세 결과의 아이콘 및 텍스트 색은 같은 결과 ViewModel에서 가져온다.

RDS의 SSM 중계 EC2/RDS 엔드포인트/로컬 포트 안내 아이콘은 hover와 클릭으로
동일한 도움말을 표시한다. 터널 더보기 버튼은 S3 객체 작업 버튼과 동일한
28px 투명·외곽선 없는 아이콘 스타일을 사용한다.

- EC2: use white terminal strokes on black 34px outer action buttons, vertically centered in
  the existing row. More buttons share the S3/RDS transparent icon style. Region input is
  at least 210px with no nested line-edit padding. Last connection uses YYYY-MM-DD HH:mm.

### Secrets 목록 compact 보정 (2026-09-21)
- 첫 줄은 기존 Secret 이름(별도 별칭 필드 없음), 우측 고정 폭 마지막 조회 시각, 24px 더보기 버튼이다.
- 둘째 줄은 `Secret ID`와 원본 ID를 같은 폭으로 표시하며 넘치는 부분은 ellipsis, tooltip은 원본 전체이다. 이전 ARN 접두부 생략 규칙보다 이 규칙을 우선한다.
- 시각은 성공 조회의 last_retrieved_at만 사용하여 로컬 `YYYY-MM-DD HH:mm`, 미조회는 `-`로 표시한다.
- 더보기 `수정하기`는 더블클릭의 edit_saved를 재사용한다. 복사/로컬 삭제 유지.
